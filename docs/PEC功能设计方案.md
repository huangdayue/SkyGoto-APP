# PEC 功能设计方案 V2

## 一、关于轮询冲突的分析

### 1.1 当前轮询架构

```
ControlViewModel.startPollingWhenVisible()
    ↓
MountRepositoryImpl.startPolling()
    ↓
每 500ms 执行 getStatus() {
    commandMutex.lock()
        :GR# (读取 RA)
        :GD# (读取 Dec)
        :GA# (读取 Alt)
        :GAz# (读取 Az)
        :Gt# (读取追踪状态)
    commandMutex.unlock()
    update mountStatus StateFlow
}
```

### 1.2 PEC 命令的冲突风险

| PEC 命令 | 耗时 | 是否会冲突 |
|---------|:---:|:---------:|
| `:$QZ?#`（查状态） | ~10ms | ❌ 基本不冲突，单条命令极快 |
| `:$QZ+#`（启用回放） | ~10ms | ❌ 同 |
| `:$QZ-#`（禁用） | ~10ms | ❌ 同 |
| `:$QZ/#`（开始录制） | ~10ms | ❌ 同 |
| `:$QZZ#`（清空） | ~10ms | ❌ 同 |
| `:$QZ!#`（保存 NV） | ~50ms | ⚠️ 写闪存略慢，但不会冲突 |
| `:GXE7#`（读蜗杆步数） | ~10ms | ❌ |
| `:VR[n]#`（读一条修正值） | ~10ms | ❌ |
| `:WR[n,sn]#`（写一条修正值） | ~10ms | ❌ |

### 1.3 结论

**PEC 命令与主轮询共用 `commandMutex` 即可，无需特殊处理。** 原因：

1. 所有 PEC 命令都是单条收发（不像 `getStatus()` 是一组命令）
2. 每条耗时 ~10ms，主轮询间隔 500ms，留有 490ms 的空闲窗口
3. 如果 PEC 命令恰好在 `getStatus()` 持锁时到达，最多等 10-50ms 就能拿到锁

**唯一需要暂停轮询的场景：** 批量读写 PEC 表数据（862 条）。这时候每条发一条 `:VR[n]#` 或 `:WR[n,sn]#`，需要连续占用串口几十秒。这种情况不多（只在首次加载曲线或保存编辑时），可以临时暂停轮询，处理完再恢复——参考对齐流程的做法。

### 1.4 实现策略

```kotlin
// PEC 单条命令：直接走 commandMutex
suspend fun getPecState(): Result<PecInfo> = commandMutex.withLock {
    val response = protocol.sendCommand(PEC_STATUS)
    // 解析...
}

// 批量读取 PEC 曲线：暂停轮询，批量读取，恢复轮询
suspend fun loadPecCurve(): Result<List<Int>> {
    pausePolling()  // 暂停主状态轮询
    try {
        val values = commandMutex.withLock {
            (0 until bufferSize).map { i ->
                protocol.sendCommand(":VR$i#")
            }
        }
        return Result.success(values)
    } finally {
        resumePolling()  // 恢复
    }
}
```

### 2.2 曲线交互细节

**默认视图：**
- 加载已有的 PEC 数据（如果有）显示曲线
- 未录制时显示空白网格 + "暂无数据" 提示
- Y 轴范围自动适配（按最大修正值 ±20% 余量）

**触摸交互：**

| 手势 | 效果 |
|------|------|
| 点击曲线上的点 | 选中该秒 → 底部弹出编辑面板 |
| 长按 + 拖拽 | 调整该点的修正值（垂直拖动） |
| 双指缩放 | 放大/缩小查看局部细节 |
| 左右拖动 | 平移曲线视图 |
| 双击 | 恢复默认缩放（全屏显示整圈） |

**视觉设计：**
- 曲线颜色：录制中为蓝色，回放中为绿色，空闲为灰色
- 修正值为零：灰色虚线
- 选中点：红色高亮圆点
- 峰值标记：自动标注最大值/最小值
- RMS 标注：右上角显示当前曲线的 RMS 误差

### 2.3 曲线数据的加载策略

```
首次进入 PEC 页面：
    ↓
发送 :$QZ?# 查状态
    ↓
如果 isRecorded=true：
    暂停轮询 → 批量读取 862 个 :VR[n]#（~4 秒）
    缓存到 ViewModel → 绘制曲线 → 恢复轮询
    ↓
如果 isRecorded=false：
    显示空曲线

编辑后：
    修改 ViewModel 缓存中的值
    点"应用"→ 单条 :WR[n,val]# 写入
    点"保存NV"→ 批量写入全部缓存 → :$QZ!#
```

**优化：** 862 次串口通信约需 4-8 秒。建议加一个"正在加载曲线..."的 Loading 动画，放在访问 NV 的分区时可以接受。如果觉得慢，可以用 `:Vr[n]#`（一次读 10 个字节）把 862 次降到 87 次，耗时 <1 秒。
